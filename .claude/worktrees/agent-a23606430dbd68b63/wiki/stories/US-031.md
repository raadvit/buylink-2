## Why / Business Goal
Aktuální design timeline/stavového řádku layoutově nezapadá do UI. Potřebujeme modernější, přehlednější prezentaci story lifecycle pro adminy. Redesign zvýší čitelnost a vizuální integraci v rozhraní.

## Co se zobrazuje
Nový timeline widget se 7 kroky (draft → done) + nový banner pod widgetem obsahující:
- Název (title) požadavku
- Data ze stavového řádku (aktuální status, poslední krok, progress)
- Stejná vizualizace kroků a barevné stavy jako teď

Banner se zobrazuje pro všechny story, obsah se mění podle statusu/dat story.

## Jak se to chová
- Přepracování CSS stylování timeline komponenty (renderTimeline)
- Přidání nového banner komponentu pod timeline widget
- Zachování stávajícího datového modelu a logiky mapování status → krok
- Stejné chování a validace, čistě vizuální refactor
- Design mockup bude k dispozici v příloze (později se uloží)
- Admini vidí stejný widget pro všechny story, jen se mění data

## Acceptance Criteria

### Funkční podmínky
- [ ] Timeline se vykreslí s novým designem pro všechny možné story statusy (draft → ready-for-arch → validated → in-development → ready-for-pr → done)
- [ ] Banner pod timeline widgetem zobrazuje: (1) aktuální status story, (2) aktuální validation fáze (Product Owner / Conflict Check / Architect), (3) poslední změnu/aktivitu
- [ ] Všechny CSS třídy (.passed = zelená, .pending = modrá s glow, .blocked = červená) se vykreslují a jsou vizuálně jasně rozlišitelné
- [ ] Timeline respektuje nový layout z US-030: stavový řádek je POSITIONOVÁN NAD timelinerem; obě komponenty jsou zarovnány a tvoří koherentní UI
- [ ] Live-update z US-020 zůstává funkční: CSS třídy se změní bez DOM refreshu, timeline se aktualizuje při polling změnách (2s interval)

### Nefunkční podmínky
- [ ] Timeline se vykreslí bez JavaScript chyb v prohlížeči console
- [ ] Performance: renderTimeline() trvá < 50ms pro single story; batch-update (polling 10 story) < 200ms
- [ ] Responsive design: Timeline se přizpůsobí viewportu — mobile (< 640px), tablet (640–1024px), desktop (> 1024px)
- [ ] CSS je optimalizováno: žádné duplikáty, konzistentní výšky/marginy, sjednocená paleta barev
- [ ] Backward compatibility: API `renderTimeline(container, storyStatus, opts)` zůstává nezměněna; volající kód se nemusí měnit

## Test Cases
- [ ] **Happy path — Vykreslenítimeline:** Admin otevře story v draftu → vidí timeline s 7 kroky, 1. krok (draft) je zelený (passed), 2. krok (conflict-check) je modrý (pending), ostatní šedé; banner pod ním zobrazuje 'Status: Draft'
- [ ] **Happy path — Progrese story:** Story se změní z draft → ready-for-arch → validated; timeline se vizuálně aktualizuje (zelené kroky rostou), banner aktualizuje status bez refreshu
- [ ] **Negative — Chybný krok:** Story je v konflikt-check a detekoval se konflikt; 2. krok (conflict-check) je červený (blocked); banner zobrazuje 'Status: Conflict Check — Konflikty detekováno'
- [ ] **Edge case — Dlouhý text v banneru:** Stavový řádek nebo název story obsahuje 100+ znaků; banner se nerozbije layoutem, text se zabalí nebo zkrátí s ellipsis
- [ ] **Edge case — Více timeline instancí:** Stránka zobrazuje seznam 5+ story; každá má svou timeline instance; všechny se vykreslí bez kolizí/chyb
- [ ] **Live update — CSS změna bez refreshu:** US-020 polling změní validation_phase; JavaScript aktualizuje CSS třídy na timeline; kroky změní barvu bez DOM refreshu (bez blikání)
- [ ] **Integrace s US-030:** Stavový řádek je nad timelinerem; obě komponenty jsou zarovnány (stejná šířka, okraje); nejsou vizuální konflikty

## Technické poznámky (Architekt)
**Dotčené komponenty:**
- `task-forge/static/shared.js`: Funkce `renderTimeline(container, storyStatus, opts?)` — renderuje 7-kroků timeline podle story statusu a validation_phase
- `task-forge/static/app.js`: Funkce `_updateTimelineForPhase()` — mapuje validation_phase na aktivní/chybný krok; volá renderTimeline()
- `task-forge/static/style.css`: CSS třídy `.passed`, `.pending`, `.blocked` — definují barvy a styly timeline kroků
- `task-forge/static/index.html`: HTML struktura timeline widgetu a panelu stavů

**Závislosti a konflikty:**
- **US-018** (Timeline stavu validace zobrazení - validace barev): Stejná komponenta, styling. Nový design musí absorbovat výsledky z US-018 nebo je zcela nahradit. Vyžaduje koordinaci.
- **US-020** (Timeline stavů - průběžná aktualizace): Live-update logika (polling 2s, CSS class switching) musí zůstat kompatibilní. CSS třídy se musí dát aktualizovat bez DOM refreshu.
- **US-030** (Přesun stavového řádku do timeline): Už je hotový. Nový design musí respektovat pozici stavového řádku NAD timelinerem. Stavový řádek a timeline tvoří nový unit — redesign obou komponent dohromady.

**Datový model:**
- Story status (`draft`, `conflict-check`, `ready-for-arch`, `validated`, `in-development`, `ready-for-pr`, `done`) → mapuje se na timeline step index (0–6) via `_STATUS_TO_STEP`
- Validation phase (`product_owner`, `conflict_detector`, `architect`) → určuje `activeStep` a `errorStep` pro timeline
- Banner pod timeline: Zobrazuje aktuální stav story + metadata ze stavového panelu (status, fáze, poslední aktivita)

**Scope změny:**
- POUZE stylování a HTML struktura (CSS, layout, barvy, ikony, text labels)
- NEJSOU změny v logice mapování statusu → kroků
- NENÍ změna v API funkce `renderTimeline()`
- Zachování kvality live-update (CSS třídy zůstávají jako vstupní bod pro JS změny bez refreshu)
