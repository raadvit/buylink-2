## Why / Business Goal
Timeline widget pokrývá veškeré informace o stavu story. Původní done-section a status-bar jsou redundantní a zbytečně komplikují UI. Cíl: zjednodušit frontend odstraněním mrtvého kódu.

## Co se zobrazuje
Kompletní odstranění dvou HTML/JS komponent:
- `#done-section` (sekce s výsledky po completionu story)
- `#status-bar` (div s třídou `status-success` zobrazující stav)

Změna se aplikuje globálně na všechny uživatele a role (ne jen adminy).

## Jak se to chová
Fyzické smazání kódu — ne CSS display:none. Odstraní se:
1. HTML elementy z `task-forge/static/index.html`
2. Příslušný JS kód vykreslující tyto komponenty ze `task-forge/static/app.js`
3. CSS styly z `task-forge/static/style.css`

Timeline widget (`renderTimeline()` v `shared.js`) plně převezme vizualizaci lifecycle story — žádné funkční deficit.

## Technické poznámky (Architekt)
**Dotčené komponenty:**
- `#status-bar` (HTML, JS v shared.js, CSS v style.css) — starší statusbar, nyní redundantní s timeline widgetem
- `#done-section` (HTML, JS v app.js, CSS v style.css) — banner "Story byla vytvořena", nahrazena timeline aktualizací

**Závislosti:**
- `shared.js`: funkce `showStatus(state, title, detail)` a `hideStatus()` se používají v:
  - `newStory()` → `hideStatus()`
  - Možné API responses (ale ne v task-forge UI)
- `app.js`: funkce `_showDoneSection(result, totalCostUsd)` se volá z `_handleFormSuccess()` (řádka 555)
  - Volání `hideStatus()` v `newStory()` (řádka 236)
  - Skrytí done-section v `_resetForm()` (řádka 225)
- `style.css`: CSS pro status-bar (řádky 76-84) a done-section (řádky 95-98, 177-178)

**Konflikt s US-030/US-031:**
US-030 a US-031 pracují se stavovým řádkem jako součástí timeline. Tato story odstraňuje `#status-bar` pod timeline (je to jiný prvek). Timeline widget (`#story-timeline-wrap`) zůstává nezměněn.

**Řešení:**
1. Odstranit HTML: `<div id="status-bar">`, `<div id="done-section">`
2. Odstranit JS: funkce `showStatus()`, `hideStatus()`, `_showDoneSection()` a jejich volání
3. Odstranit CSS pravidla pro oba prvky
4. Timeline widget zůstane beze změny (zobrazuje status story)
5. Znovu otestovat UI bez těchto prvků — timeline by měl být jediný status indicator
