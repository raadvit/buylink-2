## Why / Business Goal
Při přípravě story (draft) je levý sloupec s formulářem primární a timeline je sekundární (70/30). Po odeslání k validaci se fokus přesuwa na timeline a anotace (timeline/arch review jsou na pravé straně) — šířky se otočí (30/70) pro lepší čitelnost. V závěrečných stavech (PR, DONE) se layout vrátí na původní poměr.

## Co se zobrazuje
Celý pravý sloupec (right column) se dynamicky změní na šířku. V draftu: left=70%, right=30%. Po odeslání (conflict-check/ready-for-arch/arch-approved/in-development): left=30%, right=70%. V stavech ready-for-pr a done: left=70%, right=30% (původní). Obsah zůstává stejný, mění se jen šířka sloupců.

## Jak se to chová
Trigger: automaticky když se story status změní z 'draft' na 'conflict-check' (agentem). CSS/JS logika mapuje aktuální krok timeline (`_STATUS_TO_STEP`) na šířkový poměr. Responsive design se zachová. Přechod probíhá bez page reload — pouze CSS třídy/inline styly se změní.

## Test Cases
- [ ] Happy path: Otevřu story formulář → vyplním → kliknu 'Odeslat' → layout se změní na 280px/1fr → čekám na validaci → timeline postupuje → layout zůstane otočený až do stavu PR → pak se vrátí do 1fr/280px
- [ ] Negative: Při selhání validace (konflikty detekováno) se layout nezmění zpět — zůstane v otočeném stavu
- [ ] Edge case: Refresh stránky během validace (např. architect fáze) → layout se aktualizuje na základě aktuálního stavu z session
- [ ] Edge case: Stornování story v průběhu (back button) → layout se resetuje do normálu
- [ ] Chybový stav: Pokud fetch na /api/submit selže, layout nezmění (formulář zůstane v normální podobě)

## Technické poznámky (Architekt)
**Dotčené komponenty:**
- CSS selektor `.r-main` (grid layout s `grid-template-columns: 1fr 280px`)
- CSS třída `.layout-reversed` (nová)
- JavaScript: funkce `_updateTimelineForPhase()` v app.js
- JavaScript: funkce `_updateLayoutForStatus()` (nová)

**Datový model:**
Layout je závislý na story statusu mapovaném na timeline krok:
- `draft`, `conflict-check`, `ready-for-arch` → normální grid (1fr 280px)
- `validated` (arch-approved), `in_development` → reversed grid (280px 1fr)
- `ready-for-pr`, `done` → normální grid (1fr 280px)

**Implementační přístup:**
1. Přidat CSS třídu `.layout-reversed` v style.css s `grid-template-columns: 280px 1fr`
2. Přidat funkci `_updateLayoutForStatus(storyStatus)` v app.js, která přidává/odebírá třídu na `.r-main`
3. Volat `_updateLayoutForStatus()` z `_updateTimelineForPhase()` s příslušným statusem
4. Mapování stavu: aktualizovat `.r-main` vždy, když se změní timeline (submitForm → validated → done)
