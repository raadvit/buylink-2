## Why / Business Goal
Admin chce viditelnou kontrolu nad spuštěním implementace z frontend místo automatismu — dává explicitní control point, audit trail a deterministické chování.

## Co se zobrazuje
V timeline widgetu se přidá tlačítko 'Pustit implementaci' vpravo od timeline (do stavového řádku). Viditelné jen když je timeline na krocích 'Arch review' → 'Dev plán' nebo 'Vývoj' (story status `validated` nebo `in_development`). Po kliknutí: tlačítko se změní na disabled stav + v banner-komponenty (kočička) se zobrazí loading bar s textem typu 'Programátoři začali s prací'.

## Jak se to chová
Klik na tlačítko spustí sekvenci: (1) tlačítko disabled, (2) loading bar zapnut v banneru, (3) zavolá se POST na /implement endpoint s story ID na backendu, (4) story status se změní na in_development. Tlačítko zůstane disabled trvale — žádný reset/recovery pokud selže. Timeline se aktualizuje na základě response z backendu.

## Test Cases
- [ ] **Happy path**: Story je ve stavu `validated`, admin vidí tlačítko, klikne, tlačítko se disabluje, loading bar se zobrazí, timeline se změní na `in-development`
- [ ] **Edge case — Dvojklik**: Admin dvakrát rychle klikne (< 100ms), backend dostane jen jeden request
- [ ] **Edge case — Refresh během implementace**: Page refresh po kliknutí, tlačítko zůstane disabled, session pokračuje v pollingování
- [ ] **Negative — Network error**: Pokud `/api/implement` selhá (timeout, 500), zobrazit chybu a tlačítko zůstane disabled
- [ ] **Negative — Nesprávný state**: Backend vrátí 400 (story není v `ready-for-arch`/`validated`), zobrazit chybu "Story není v správném stavu"
- [ ] **Negative — Neoprávněný přístup**: Non-admin uživatel by neměl vidět tlačítko vůbec
- [ ] **Negative — Story s chybou**: Story má status `conflict-check` (konflikt), tlačítko se neobjevuje
- [ ] **Chybový stav — GitHub API selhání**: Backend se nepodaří aktualizovat issue, vrátit 500 s detailem

## Technické poznámky

### Frontend komponenta

**Umístění**: Timeline widget v `shared.js` → funkce `renderTimeline()` → `bannerHtml`

**Komponenta**: Tlačítko "Pustit implementaci" se renduje v pravé části statusbaru (banner pod timelinerem), vedle textového labelu.

**Podmínka zobrazení**: Tlačítko se zobrazí pouze když:
- Story status je `ready-for-arch` NEBO `validated`
- (Ekvivalentně: modrý puntík timeline je na kroku `arch-approved` (dev plán) nebo `in-development` (vývoj))

**HTML struktura**: 
```html
<button id="btn-run-implementation" class="btn-implementation" disabled>
  Pustit implementaci
</button>
```

**Stavy**:
- **Normální**: Tlačítko je viditelné, enabled, user jej může kliknout
- **Po kliknutí**: Tlačítko se okamžitě disabluje (disabled attribute), zůstane disabled po dobu zbytku session (není reset)
- **Network error**: Chyba se zobrazí v inline chybové zprávě pod timelinerem

**Interakce**:
1. Admin klikne na tlačítko
2. Frontend zavolá `POST /api/implement` s `{story_id: <číslo>, issue_number: <číslo>}`
3. Tlačítko se okamžitě disabluje
4. Loading bar se zobrazí (existující komponenta `showProgressBar()` s textem "Programátoři pracují na implementaci")
5. Backend spustí `/implement <story_id>` CLI agent asynchronně
6. Frontend pokračuje v pollingování `/api/session` (existující mechanismus) — timeline se aktualizuje na status `in-development`

### Backend endpoint

**Endpoint**: `POST /api/implement`
- **Body (JSON)**: `{ story_id, issue_number }` nebo pouze `{ issue_number }`
- **Odpověď (success)**: `{ success: true, session_id }` (HTTP 202)
- **Odpověď (failure)**: `{ error: "..." }` (HTTP 400/500)

**Logika**:
1. Ověř, že GitHub issue existuje a je typu "user story"
2. Zkontroluj, že status je `ready-for-arch` nebo `validated` (bezpečnostní check)
3. Spusť CLI: `claude /implement --story-id=<číslo>` v background vláknu
4. Vrátí hned HTTP 202 s session_id (bez čekání na výsledek)
5. Session.status se nastaví na `in_development` (nebo `reviewing`, dle implementace)
6. GitHub issue se aktualizuje se statusem `in-development`

### Datový model

Nová entita/flag v session objektu:
- `implementation_initiated`: boolean (true když admin klikne na "Pustit implementaci")
- Timeline status: story se změní na `in_development` v GitHub body

### Bezpečnost

- Backend **musí ověřit** že story je ve správném stavu před spuštěním `/implement`
- Tlačítko se ukazuje jen adminu (role-based, frontend check) a jen v příslušných stavech
- Request musí být atomic (либо se spustí, nebo ne — bez čiastkového stavu)

### Error handling

- Pokud network call selže: zobrazit modal "Chyba připojení" s možností retry
- Pokud backend vrátí 400 (nesprávný state): zobrazit "Story není v správném stavu, překoči stránku"
- Pokud 500: obecná chyba "Chyba serveru, zkus později"
- Tlačítko zůstane disabled i po chybě (user musí refreshnout stránku)

### CSS styling

- Tlačítko se styluje jako `.btn-implementation`, barva zelená (`#43a047`), shodná s timeline `.passed` stavem
- Padding/velikost: shodný s ostatními tlačítky v banneru
- Disabled stav: opacity `0.5`, cursor `not-allowed`, bez hover efektu
