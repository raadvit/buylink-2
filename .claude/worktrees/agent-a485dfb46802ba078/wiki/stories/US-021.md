## Why / Business Goal
Admin potřebuje efektivně pracovat se story připravenými na testování. Bez filtru musí procházet všechny story; filtr umožní izolovaný pohled na testing queue.

## Co se zobrazuje
V popup 'načíst myšlenku' se zobrazí nový filtr s možnostmi: 'všechny' (default) a 'ready for testing'. Po výběru 'ready for testing' se v seznamu zobrazí jen story s tímto labelem. Filtr je single-select dropdown nebo radio tlačítko.

## Jak se to chová
Uživatel otevře popup → vybere filtr 'ready for testing' z dropdown → seznam se přefiltruje a zobrazí jen story s label 'ready for testing'. Label se na story přidává automaticky po /implement, filtrování probíhá na frontend straně. Filtr lze vrátit na 'všechny' a znovu vidět celý seznam.

## Acceptance Criteria

### Funkční podmínky
- [ ] Po spuštění /implement se k issue s labelem 'user story' automaticky přidá GitHub label 'ready-for-testing'
- [ ] V popup 'Načíst myšlenku' se v hlavičce zobrazí filtr (dropdown) s volbou 'ready for testing'
- [ ] Vybrání filtru 'ready for testing' zobrazí jen issues s GitHub labelem 'ready-for-testing'
- [ ] Zrušení filtru nebo volba 'Všechny' zobrazuje všechny relevantní issues
- [ ] Filtr je single-select - aktivní je jen jeden najednou
- [ ] Filtrování se provede bez výrazného zpoždění (< 500ms)

### Nefunkční podmínky
- [ ] GitHub label je pojmenován 'ready-for-testing' (malá písmena, pomlčky dle GitHub konvence)
- [ ] Status v kódu je ready_for_testing (Python konvence - podtržítka)
- [ ] Filtr je přístupný klávesnicí (Tab, Shift+Tab, Enter)
- [ ] Filtr zůstává vybraný i po zavření a opětovném otevření popup
- [ ] Timeline widget korektně mapuje ready_for_testing status na krok v timeline

## Test Cases
- [ ] Happy path: Otevři popup 'Načíst myšlenku' → vidíš filtr dropdown → vyber 'ready for testing' → seznam zobrazí jen issues s tímto labelem
- [ ] Happy path 2: Po /implement na issue s labelem 'user story' → GitHub automaticky přidá 'ready-for-testing' → issue se zobrazí v filtrovaném výpisu
- [ ] Negative: Filtr 'ready for testing' vybrán → v repozitáři nejsou issues s labelem → vidíš prázdný seznam
- [ ] Negative 2: Popup otevřen bez filtru → vidíš všechny issues (i bez 'ready-for-testing')
- [ ] Edge case: Issue má víc labelů včetně 'ready-for-testing' → zobrazí se v filtrovaném výpisu
- [ ] Edge case 2: Filtr změněn během otevřeného popup → seznam se aktualizuje bez uzavření/otevření
- [ ] Chybový stav: /implement skončil s chybou → label 'ready-for-testing' se nepřidá → issue chybí v filtrovaném výpisu
- [ ] Chybový stav 2: GitHub API vrátí chybu → UI zobrazí chybovou hlášku nebo fallback (prázdný seznam)
