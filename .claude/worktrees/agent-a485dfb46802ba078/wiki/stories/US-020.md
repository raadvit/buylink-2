## Co se zobrazuje
Stejná timeline, jen měníme barvy dle aktuální logiky

## Jak se to chová
Barvy se nemění na refresh stránky, ale jsou měněny automaticky jakmile agenti dokončí / začnou svůj kus práce. Tzn. koukám na web v pravé části vidím progress bar a v timeline stavů se mi mění barvičky

## Acceptance Criteria

### Funkční podmínky
- [ ] Timeline se zobrazuje správně během všech 4 fází validace (PO → Conflict → Architect → Done)
- [ ] Po refresh stránky se timeline vrací na aktuální stav (z session), ne na počátek
- [ ] Barvy se mění automaticky bez refresh kdy se změní `validation_phase` (polling 2s)
- [ ] Jednotlivé kroky se stávají 'passed' po úspěšné fázi (zelená)
- [ ] Aktuálně běžící fáze je 'pending' (modrá s efektem)
- [ ] Fáze s konfliktem/chybou je 'blocked' (červená) a zastaví postup
- [ ] Na Done se všechny kroky stanou 'passed' (zelená)

### Nefunkční podmínky
- [ ] Aktualizace timeline nepřeruší uživatelův interaction (plynulé)
- [ ] Polling interval 2s je dostatečný pro percepci real-time
- [ ] CSS animace/transition nejsou jarring (smooth color/style changes)
- [ ] Timeline zůstává viditelný a čitelný při všech stavech (contrast ratio ≥ 4.5:1)

## Test Cases
- [ ] Happy path: Vytvořit story → vidím Draft (pending) → PO skončí (Draft passed, Conflict pending) → Conflict OK (Conflict passed, Arch pending) → Arch OK (Arch passed, Dev-plan pending) → Done (všechno passed/green)
- [ ] Negative: Conflict narazí na konflikt → Conflict step se změní na red (blocked), postup se zastaví
- [ ] Edge case: Refreshnout browser uprostřed fáze PO (polling) → timeline zobrazí správný stav bez resetování
- [ ] Edge case: Refreshnout browser po Done → timeline zůstane 'done' se všema kroky passed
- [ ] Chybový stav: Agent selže (status=error) → timeline zobrazí poslední platný stav bez zmátení
- [ ] UI refresh: Změní se phase → styl se změní bez page jump/flicker

## Technické poznámky (Architekt)
**Dotčené komponenty**: Frontend timeline (shared.js `renderTimeline()`, app.js `_updateTimelineForPhase()`); Backend polling endpoint (`/api/session`) a session state management (store_state.py); CSS stavy `.impl-step` (passed/pending/blocked).

**Datový model**: Session obsahuje `validation_phase` (product_owner|conflict_detector|architect|done) a `status` (reviewing). Timeline má 7 kroků mapovaných na fáze. Barvy se určují CSS třídami: passed (zelená #43a047), pending (modrá #1976d2), blocked (červená #e53935).

**Real-time mechanismus**: Prodloužit existující polling (2s interval) + optimalizovat rerenderování. Na refresh se má timeline vykreslit aktuální stavem ze session, ne reset. Timeline se měnit auto když se změní `validation_phase` v session response.

**Kritické**: Timeline nyní resetuje na refresh protože se počítá jen z `storyStatus` (draft/validated/done). Musí se kombinovat `storyStatus` + `validation_phase` pro během-procesu stavy.
