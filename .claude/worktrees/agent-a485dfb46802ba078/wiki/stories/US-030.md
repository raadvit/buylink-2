## Why / Business Goal
Zlepšit orientaci uživatele v životním cyklu story. Story má komplexní workflow (draft → conflict-check → arch review → vývoj → PR → done), uživatel musí vidět aktuální stav. Timeline je visuálně srozumitelnější než holý status text. Konzistentnější UX across všech entry pointů (draft, idea, bug report).

## Co se zobrazuje
Stavový řádek (status + relevantní info/linky) se zobrazuje NAD timelineovou vizualizací. Timeline má 7 kroků (draft → konflikt → arch review → dev plán → vývoj → PR → done). Řádek se aktualizuje podle stavu story. Zobrazuje se ve 4 use casech: (1) Uložit story na později, (2) Vytvořit myšlenku, (3) Nahlásit bug, (4) Normální flow zadání story.

## Jak se to chová
Komponenta timeline se přesune do horní části story display. Stavový řádek s textovým statusem se umístí přímo nad timeline. Barvy timeline zůstávají stejné (zelená = úspěšně, šedá = čekající). Text v řádku se aktualizuje podle story stavu (draft → conflict-check → ready-for-arch → validated → in_development → ready-for-pr → done). Timeline se začne ukazovat u všech 4 use casů (byla doposud vidět jen u hlavního flow). Stavový řádek může obsahovat dynamické linky/akce relevantní ke stavu (např. odkaz na conflict report, arch annotations, atd.).

## Technické poznámky (Architekt)
Story představuje UI refactoring zaměřený na zlepšení viditelnosti stavu user story v aplikaci Task-Forge. Aktuálně se timeline widget (`renderTimeline()` v shared.js) zobrazuje pouze po uložení draftu v hlavní formulář (index.html), zatímco status bar (`showStatus()` v shared.js) se zobrazuje u všech akcí. 

Dotčené komponenty:
1. **shared.js** - obsahuje `renderTimeline()` a `showStatus()` - žádné změny
2. **app.js** - funkce `createIdea()` musí zobrazit timeline stejně jako `saveForm()`; funkcí `submitForm()` a `handleSessionData()` již timeline zobrazují správně
3. **bug.js** - funkce `submitBug()` musí zobrazit timeline po vytvoření issue
4. **index.html** - div `#story-timeline-wrap` (řádky 57-59) se přesune výše v DOM, aby byl nad status bar (řádky 12-17) - bude v sekci `.r1` nebo hned pod `#status-bar`
5. **bug.html** - přidat nový div `#story-timeline-wrap` se stejnou strukturou jako v index.html (vytvořit po řádce 17, podobně jako v index.html)
6. **style.css** - CSS pro timeline a status bar již existuje; flexbox layout zvládne změnu pořadí bez dalších změn

Dataový model: timeline status se mapuje přes `_STATUS_TO_STEP` v shared.js - 'draft' status se mapuje na 'draft' krok. Pro 'idea' a 'bug' se budou zobrazovat se statusem 'draft'.

Architektonické rozhodnutí: timeline zobrazujeme se statusem 'draft' u všech use casů (story, idea, bug) - není potřeba rozlišovat mezi nimi.
